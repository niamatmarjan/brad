### 1. Description

An independent QA security and robustness audit of feature `feat/sla-analytics` uncovered two critical issues affecting `GET /api/analytics/sla-summary`:

1. **Missing Role-Based Access Control (RBAC Breach / Principle of Least Privilege):**  
   The new operational analytics endpoint `/api/analytics/sla-summary` was registered without `requireRole` authorization middleware. Consequently, any authenticated user—including individual contributors such as `ENGINEER` and `QA_ENGINEER`—could query and view high-level, cross-organizational operational SLA summaries, category/priority distributions, and executive risk metrics. In addition, existing unit test suite `server/tests/analytics.test.mjs` inadvertently codified this vulnerability by asserting HTTP 200 OK for `ENGINEER` and `QA_ENGINEER`.

2. **Unsanitized Date Parsing & NaN Sort Poisoning:**  
   The `topAtRisk` aggregation pipeline relied on a truthiness filter (`.filter(r => r.target_completion_date)`) and directly executed `new Date(r.target_completion_date).getTime() - now`. Whitespace-only strings (e.g., `'   '`) evaluate to truthy, producing `NaN` for both the timestamp and the time difference (`diffMs`). In JavaScript, `NaN` in `.sort((a, b) => a.diffMs - b.diffMs)` violates strict weak ordering, resulting in array sorting corruption. Legitimate severely overdue requests were buried while unparseable dates were placed at index 0 of `topAtRisk` and falsely classified as `ON_TRACK` with `hoursRemaining: null`.

### 2. Steps to Reproduce

#### Part A: Security & Authorization Defect (RBAC)
1. Initialize test server and seed standard user accounts (`seed(db)`).
2. Issue an authenticated request to `GET /api/analytics/sla-summary` with headers:
   - `x-user-id: USR-DEV-01`
   - `x-role: ENGINEER`
3. Inspect the response status code and payload.

#### Part B: Date Parsing & Sort Poisoning Defect
1. Insert or update a request record where `target_completion_date = '   '` (ID: `REQ-101`).
2. Insert or update an overdue request record with a deadline 12 hours in the past (ID: `REQ-102`).
3. Insert or update an on-track request with a deadline 24 hours in the future (ID: `REQ-103`).
4. Issue `GET /api/analytics/sla-summary`.
5. Inspect `res.data.statusCounts` and `res.data.topAtRisk`.

---

### 3. Expected vs Actual Behavior

#### Part A (RBAC):
- **Expected Behavior:** Access to executive SLA summaries must be restricted to management and governance personas: `ADMIN`, `PRODUCT_OWNER`, and `APPROVER`. Unprivileged roles (`ENGINEER`, `QA_ENGINEER`) must be rejected with **HTTP 403 Forbidden** (`ok: false`).
- **Actual Behavior:** Endpoint returns **HTTP 200 OK** (`ok: true`), exposing full executive summary data, status counts, and risk queues to unauthorized roles.

#### Part B (Date Parsing & Sorting):
- **Expected Behavior:** Whitespace-padded strings must be trimmed and validated (`Number.isFinite(targetMs)`). Invalid or blank target completion dates must either be rejected or excluded from `topAtRisk` (classified as `NOT_CONFIGURED`). The `topAtRisk` array must reliably sort legitimately overdue/at-risk items first without `NaN` corruption.
- **Actual Behavior:**
  - `REQ-101` with `'   '` is admitted into `topAtRisk`.
  - `REQ-101` SLA status evaluates to `ON_TRACK` and `hoursRemaining` evaluates to `null` (`NaN` in JSON).
  - `topAtRisk` comparator returns `NaN`, leaving `REQ-101` at index 0 and ranking it ahead of `REQ-102` (which is 12 hours overdue).

### 5. Remediation Requirements

1. **Add Authorization Middleware:** Apply `requireRole(ROLES.ADMIN, ROLES.PRODUCT_OWNER, ROLES.APPROVER)` to `GET /api/analytics/sla-summary` in `server/src/api.mjs`.
2. **Defensive Date Sanitization:** In `calculateSla` and `topAtRisk`, trim input strings (`targetDateStr?.trim()`) and validate parsed timestamps (`!Number.isNaN(targetMs) && Number.isFinite(targetMs)`). Exclude unparseable/blank dates from `topAtRisk`.
3. **Correct CI Tests:** Update `server/tests/analytics.test.mjs` to assert HTTP 403 Forbidden for `ENGINEER` and `QA_ENGINEER`, and assert HTTP 200 OK for `ADMIN`, `PRODUCT_OWNER`, and `APPROVER`.

### 6. Remediation Summary

**Resolved By:** Platform Developer (Dev C / Feature Team)  
**Date Resolved:** 2026-10-20  
**Commit:** `542e5221e1f841b3c6122b981b076efba1ed7e60` (`542e522`)  
**Resolution Summary:**
1. **Authorization Middleware Added:** Applied `requireRole(ROLES.ADMIN, ROLES.PRODUCT_OWNER, ROLES.APPROVER)` to `GET /api/analytics/sla-summary` in `server/src/api.mjs`. Requests from `ENGINEER` and `QA_ENGINEER` are now rejected with `403 Forbidden`.
2. **Defensive Date Sanitization:**
   - Updated `calculateSla` to validate string types, trim whitespace, and guard with `Number.isFinite(target)`. Unparseable or whitespace-only target dates now return `SLA_STATUS.NOT_CONFIGURED` with `hoursRemaining: null`.
   - Updated `topAtRisk` aggregation pipeline to filter items ensuring `r.target_completion_date && r.target_completion_date.trim() !== '' && Number.isFinite(new Date(r.target_completion_date.trim()).getTime())`. Items with invalid or whitespace dates are excluded from `topAtRisk`, preventing `NaN` diffs and eliminating sort poisoning.
3. **Automated Test Updates:**
   - Updated `server/tests/analytics.test.mjs` to assert 403 Forbidden for `ENGINEER` and `QA_ENGINEER`, and 200 OK for `ADMIN`, `PRODUCT_OWNER`, and `APPROVER`.
   - Updated `server/tests/analytics_qa.test.mjs` to verify RBAC enforcement and verify that whitespace-only dates are classified as `NOT_CONFIGURED` and excluded from `topAtRisk`.

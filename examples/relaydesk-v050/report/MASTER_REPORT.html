3. RelayDesk Application Architecture

RelayDesk coordinates service requests through two functional modules and a shared platform foundation:

  • Module A (Intake & Approvals): Creation, acceptance criteria definition, categorization, priority, departmental approval/rejection gates.
  • Module B (Fulfillment & QA): Assignment, in-progress tracking, blocker flagging/clearing, peer review, QA gate verification, and defect retesting.
  • Shared Platform: Role authorization, SQLite persistence, optimistic concurrency control (version matching), dynamic SLA calculation, HMAC webhook dispatcher, and CSV/JSON audit export.
API: Express on Node 24 | DB: SQLite DatabaseSync | UI: React 19 + Vite 6

8. Confirmed Findings & Root Causes

FND-001: Native BMAD specialist skills can be invoked directly by BRAD when installed. HIGH

Observed: Host environment lacks native BMAD CLI/skills in host catalog. BRAD doctor reports 'BMAD Method not detected'. Direct L4/L5 execution is blocked without host installation.

Root Cause: BMAD is a user-installed prerequisite, not bundled into BRAD core distribution.

Proposed Fix: Add clearer diagnostic guidance in `brad doctor` explaining exact one-step command to install BMAD in current host (e.g. npx bmad-method install or agent-specific setup). (Affected: cli/core.mjs, skills/brad/scripts/inspect_bmad.py)

FND-002: BRAD should distinguish extending an approved module increment from authoring a greenfield PRD. MEDIUM

Observed: Conditional routing for increment-level changes can collapse to generic PRD generation if no explicit story ID is supplied.

Root Cause: Lack of explicit keyword resolution for 'increment' / 'delta' in regex matcher.

Proposed Fix: Add increment-aware keyword routing in SKILL.md and epics-and-stories.md guidance. (Affected: skills/brad/SKILL.md, skills/brad/references/epics-and-stories.md)

FND-003: Read-only review requests must not propose code modifications or PR generation. MEDIUM

Observed: Ticket-to-PR default can over-eagerly propose branch and PR creation on review requests unless --plan / read-only is emphasized.

Root Cause: Rule priority #4 ('One command, one requested outcome') default to PR delivery needs stronger guardrails against review-only intents.

Proposed Fix: Reinforce Rule #1 and ticket-to-pr contract that 'review' intents strictly forbid write actions without explicit override. (Affected: skills/brad/SKILL.md, skills/brad/references/ticket-to-pr.md)

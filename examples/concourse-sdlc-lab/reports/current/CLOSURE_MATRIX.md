## Decision boundary

The API's acceptance of empty or omitted criteria is now directly observed, but AC-04 remains BLOCKED until its oracle is approved. Similarly, implementation permission guards and selected denied-request tests do not make AC-02 pass without an approved matrix. These are acceptance/specification gaps, not proof of an application defect.

## Independent review observation

A separate read-only code-review context found the API contract / AC-04 wording conflict: omission is not marked optional in the contract, while the acceptance matrix explicitly says required-vs-optional is unspecified. The reviewer did not execute the endpoint; this run's separate in-memory HTTP probe did. The conflict is recorded as an unresolved specification decision, not silently adjudicated as an application defect or a passing requirement.

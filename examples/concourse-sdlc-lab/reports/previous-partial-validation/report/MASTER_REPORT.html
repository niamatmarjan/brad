  • Implemented in the prototype: task CRUD, status changes, search/priority/assignee/project filtering, notes, recent activity, responsive board/list, seeded fictional personas.
  • Not implemented: real organizations/accounts, server-side authorization, database/API, multi-user sync, durable shared notifications, production audit history, external integrations, deployment.

08

Architecture

The app uses Node built-in HTTP to serve static assets from localhost; browser ES modules hold domain helpers and localStorage contains client data. No npm runtime dependencies or production services are required.

Browser UI (public/index.html + app.mjs) ├── domain rules (src/domain.mjs) ├── localStorage (single-browser persistence; no server identity) └── Node HTTP static server (server.mjs) └── 127.0.0.1 only · path containment · CSP / nosniff

This was chosen for a reproducible no-install demo. It is not a reviewed production design. No native Architect, security, or NFR workflow ran; no database schema, API contract, ADR approval, or threat model was established.

Security & safety

  • No credentials, private transcripts, customer data, remote repository, or production service was used.
  • BRAD and BMAD setup were confined to temporary directories; no project-global BMAD configuration change.

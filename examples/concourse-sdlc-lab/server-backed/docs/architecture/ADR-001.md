# ADR-001: Local server-backed application

- **Status:** Accepted for the local MVP; production suitability is not implied.
- **Decision:** Use a typed React/Vite browser client and a local Node.js HTTP service backed by SQLite. Use the Node 24 built-in SQLite interface to avoid native package installation risk on Windows. Persist users, sessions, projects, work items, transition history, comments/activity, review decisions, QA runs, defects, and retests.
- **Authorization:** Demo-account switching is development-only. The server resolves the user from a random, opaque, HttpOnly, SameSite cookie backed by a revocable database session. Every mutation checks the role and domain transition on the server. This mechanism is a local demonstration boundary, not production identity.
- **Concurrency:** SQLite WAL and short transactions; each mutable record has an integer version. Mutations compare the submitted `expectedVersion` and return `409` on stale writes.
- **UI development:** Vite serves the client in development and proxies `/api`; the app service serves the built client for a single-command local demo.
- **Consequences:** No external services are required. Node 24+ is required. Manual refresh is the documented cross-session synchronization guarantee; no real-time claim is made. Separate disposable database files are used for developer/QA runs.
- **Alternatives considered:** A hosted database and OAuth add external dependencies outside the offline-demo scope. A localStorage-only app cannot provide shared server authorization, durable cross-session state, or stale-write detection.

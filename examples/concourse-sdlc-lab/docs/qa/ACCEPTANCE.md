# MVP acceptance matrix

**QA-01 · pre-implementation review · branch `qa/functional`**

This matrix was authored before implementation from `docs/product/MVP.md`, `docs/api/CONTRACT.md`, and `docs/sprints/MVP.md`. The status column and execution evidence below reflect the integrated implementation; unresolved specification gaps remain explicit, and no endpoint or result is presumed beyond the cited evidence.

**Execution status:** mixed. Cases were exercised against integrated commit `88b1d7c2b4d6ba54f866463dc2cbf167aba7547b` on Node 24.19.0; see the execution record below. A case is not marked PASS when its required oracle is still a specification gap. “Expected” describes the contract, not an observed result. `SPEC GAP` flags an acceptance detail that must be agreed before an unambiguous pass/fail decision.

## Journeys

1. Sign in as a seeded demo user and access the shared project according to role.
2. Plan a project story with acceptance criteria, ownership, and sprint organization.
3. Deliver and review a story through server-validated workflow transitions.
4. Run QA, file a blocking defect, fix it, retest, and close it with history.
5. Check release readiness and persisted audit history across browser sessions.

No merge, tag, GitHub Release, npm registry publication, or production change is authorized. The currently published release remains [v0.5.1](https://github.com/niamatmarjan/brad/releases/tag/v0.5.1). Review and finalize this draft before a release-authorized merge.

## What would change from v0.5.1

- **Explicit native BMAD setup:** `brad setup --with-bmad` invokes the official upstream stable installer only after opt-in, with project-local target scope. Ordinary `brad setup` remains BRAD-only.
- **Safer unattended onboarding:** explicit module/tool selection for non-TTY stable installs (e.g. `--bmad-modules bmm,tea --bmad-tools antigravity --non-interactive`); missing headless configuration fails quickly instead of hanging. The live opt-in path cannot use `--json`; `--dry-run --json` remains read-only.
- **Process and installation safety:** bounded upstream execution timeout and descendant cleanup, existing BMAD runtime/skills skip without migration or overwrite, and honest upstream-file/host-verification status.
- **Host diagnostics:** project native-skill inventory detects Antigravity's official `.agent/skills` directory as well as the BRAD-host installation directories. `doctor` is still read-only and cannot assert that a native host workflow was actually invoked.
- **Preview caution:** the v7 alpha `--bmad-channel preview` option is opt-in and requires an interactive environment and further native host setup; live v7 compatibility has **not** been accepted in this validation workstream.

## Prospective installation (only AFTER a v0.5.2 release is approved and published)

From a project root with Node.js 20+ and Git:

```powershell
# For the prospective tagged v0.5.2 release only — do not run against a nonexistent tag yet:
npx.cmd --yes "github:niamatmarjan/brad#v0.5.2" setup --agent antigravity

# Explicit official stable BMAD opt-in; headless:
npx.cmd --yes "github:niamatmarjan/brad#v0.5.2" setup --agent antigravity --with-bmad --bmad-modules bmm,tea --bmad-tools antigravity --non-interactive

# Inspect local state:
npx.cmd --yes "github:niamatmarjan/brad#v0.5.2" doctor --agent antigravity --json
```

On Linux/macOS use `npx` rather than Windows `npx.cmd`. The project must permit installation of the selected official upstream runtime. Existing native installations are not silently upgraded. Completion does **not** prove actual host catalog registration; refresh and inspect the coding host's real skill list and invoke an appropriate native workflow if needed.

## Prerequisites and limitations

- The BRAD installer itself requires Node.js 20+ and Git; **some installed BMAD Build workflows** also use the Python `uv` command to render workflow instructions. In an observed Windows Claude Code session, native `bmad-build` used `uv`. Verify `uv --version` when that installed native workflow calls for it; do not conflate `uv` with a required BRAD CLI dependency or install global tooling silently.
- In local Windows testing, default-concurrency `npm test` intermittently encountered temporary-directory file-lock failures, while `node --test --test-concurrency=1 tests/*.test.mjs` passed 52/52. A later operator reported 3/3 passing default-parallel reruns, and Windows CI also passed. This is a **watch item**, not a proven permanently resolved root cause.
- BMAD v7 alpha workflow compatibility, authenticated native TEA execution in Copilot and universal host-native Build/TEA activation are **not validated**.
- This is still a **supervised preview**, not autonomous production delivery. Human consent is needed for consequential remote writes, upgrades, merges and deployments.

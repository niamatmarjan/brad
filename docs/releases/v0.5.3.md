# BRAD v0.5.3 — native skill inventory correction (DRAFT / NOT PUBLISHED)

**Status:** A supervised-preview *release candidate* on `release/v0.5.3-rc`, not a released tag. Latest public release: [v0.5.2](https://github.com/niamatmarjan/brad/releases/tag/v0.5.2). Source version 0.5.3 exists only in the isolated test branch; this document **does not authorize merging, tagging or publication**.

## Changes

- Fix `skills/brad/scripts/inspect_bmad.py` to inventory project-local BMAD native skills in both **`.agent/skills`** (used by official stable BMAD's Google Antigravity installer) and **`.agents/skills`** (shared skills and v7 Skills CLI), plus `.codex/skills` where native skills reside. Preserve existing `.github/skills` and `.claude/skills` detection.
- Add three tests: Antigravity 39-skill-style v6/TEA hints, duplicate Codex/shared roots, and v7 hub/ticket hints that remain conservative and do not assert runtime presence or real host dispatch.
- No modifications to BRAD's already released v0.5.2 CLI setup, nested npm installer, Windows bounded rename retry, native BMAD workflow code, or upstream project state.

## Reproduced defect and evidence

In a real disposable Windows Antigravity 1.1.12 project with official BMAD v6.12.4 (BMM + TEA), the operator reported the released v0.5.2 Python inspector missed all **39 native BMAD skills** under singular `.agent/skills` and falsely reported `tea:false` / `version_hint_not_proof:unknown`. The same workspace with [PR #35's fix](https://github.com/niamatmarjan/brad/pull/35) detected all 39, `tea:true`, `v6_likely`, and retained the warning that version hints are not guaranteed identification.

- Operator Windows Python tests: **28/28** PASS on the patched source.
- [PR #35 CI run 40006077565](https://github.com/niamatmarjan/brad/actions/runs/40006077565): **8/8 verification jobs PASS**, including Python 3.11/3.12 and Windows Node 22/24 **54/54** suites.
- Further **candidate-stamped** package and installer tests are required and must be recorded before any release approval.

These facts demonstrate correct **read-only file inventory** in the tested paths, not independent native BMAD skill execution. See [issue #34](https://github.com/niamatmarjan/brad/issues/34) and [cross-host findings #33](https://github.com/niamatmarjan/brad/issues/33).

## Proposed installation (only after explicit publication)

```powershell
# In an authorized project (Windows); on macOS/Linux use npx
npx.cmd --yes "github:niamatmarjan/brad#v0.5.3" setup --agent antigravity
npx.cmd --yes "github:niamatmarjan/brad#v0.5.3" doctor --agent antigravity --json
```

BRAD is a thin **router around separately installed official BMAD**. Ordinary setup does not install BMAD. Explicit opt-in stable BMAD setup was introduced in v0.5.2; it is still approval-gated. The released **v0.5.2** tag should be used for actual installation until v0.5.3 is published.

## Host/version limitations (not resolved by this patch)

- **Stable v6.12.4:** installation and native skill inventory have bounded observed Windows Antigravity results. A two-test synthetic `/health` endpoint task used native workflow instructions **inline**, not a proven separately dispatched host-native Build/TEA tool event for each role.
- **v7 preview alpha:** Skills CLI installed some native skills (operator reported 30) but `bmad-retrospective` reported an upstream YAML parse error; Windows `setup.py` initially failed an upstream staging rename with `WinError 5` then succeeded on retry. A full genuine v7 ticket→Build→review/TEA E2E test remains **NOT_VERIFIED** ([#32](https://github.com/niamatmarjan/brad/issues/32)).
- **Codex:** the host CLI was absent in the operator's Windows shell; **NOT_RUN**. **Claude Code:** v0.5.2 execution blocked by missing login session; **NOT_RUN**. **Copilot CLI:** installed skills were listed, but actual native workflow execution **NOT_RUN** ([#33](https://github.com/niamatmarjan/brad/issues/33)).
- **ChatGPT / Claude.ai web chats:** connector access is not proof of local BMAD native skill invocation.
- Historical public repository path/session metadata and other security caveats remain as recorded in [#16](https://github.com/niamatmarjan/brad/issues/16); no zero-risk claim.

# Definition of Done

A work item is done only when the team can point to the required evidence:

- Acceptance criteria are met or explicitly deferred by the authorized owner.
- Implementation is limited to approved scope; no unrelated or user-owned changes were overwritten.
- Relevant focused tests were executed and their exact command, exit status, and result are recorded.
- Applicable code review, accessibility, security, and quality gates were completed or transparently blocked.
- Documentation, migration, compatibility, and recovery notes are updated where applicable.
- Native ticket state reflects the actual outcome; no second tracker was silently updated.
- Branch/commit and real PR/CI URLs are recorded only when those events actually occurred.
- Known defects, residual risks, approvals, and release blockers remain visible.

Generated code, test files, a proposed route, or a verbal completion statement alone do not meet this definition. Merge, deploy, release, and publication require their own authorization. This is a recommended checklist, not a completion claim for the full study.
